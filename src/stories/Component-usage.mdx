# コンポーネントの使い分け

## `/elements` と `/ui` の使い分け

コンポーネントを実装する際は、原則として `/elements` に定義されているコンポーネントを使用してください。

`/elements` は、プロジェクト内で共通利用する基本的なコンポーネントを提供するディレクトリです。スタイルやインターフェースが統一されており、Storybook による表示確認やテストも整備されています。

一方、`/ui` は shadcn/ui などをベースとした、より低レベルな UI コンポーネントを提供するディレクトリです。

`/elements` に該当するコンポーネントが存在しない場合や、`/elements` では実現できない機能が必要な場合に `/ui` を使用してください。

### 基本方針

| ディレクトリ | 用途 | 使用方針 |
| ------------ | ---- | -------- |
| `/elements` | 共通利用する基本コンポーネント | 原則こちらを使用する |
| `/ui` | 低レベルな UI プリミティブ | `/elements` で対応できない場合に使用する |

### `/ui` を使用する例外

以下のケースでは `/ui` のコンポーネントを直接使用して構いません。

| コンポーネント | 使用するケース | 補足 |
| -------------- | -------------- | ---- |
| `Button` | ボタンの表示・動作を個別にカスタマイズしたい場合 | `/elements` に共通ボタンがない場合や、独自の組み合わせが必要な場合 |
| `Dialog` | ダイアログの構造や制御を独自に実装する場合 | `Dialog`、`DialogContent` などを組み合わせて使用 |
| `AlertDialog` | 確認・警告ダイアログを実装する場合 | 確認操作を伴う UI に使用 |
| `Popover` | ポップオーバーの表示制御を独自に実装する場合 | `/elements` のコンポーネントで対応できない場合 |
| `Tooltip` | ツールチップを独自の UI に組み込む場合 | 表示位置やトリガーを制御する場合 |
| `Drawer` | ドロワー形式の UI を実装する場合 | モバイル向けメニューなど |
| `Card` | カードの構造を独自に組み立てる場合 | 共通の Card コンポーネントで対応できない場合 |
| `Separator` | UI 内に区切り線を配置する場合 | レイアウト上の補助要素として使用 |
| `Table` | テーブルを作成する場合 | テーブルは画面ごとに仕様が異なるため、必要に応じて個別に構築 |

※ 上記は代表例です。`/elements` に同等の機能を持つコンポーネントがある場合は、そちらを優先してください。

### レイアウトコンポーネントの使用

UI 要素の配置やレイアウトには、原則として既存のレイアウトコンポーネントを使用してください。

レイアウトやスタイリングを目的として、`div` などの HTML 要素を直接使用することは避けてください。

既存の `components/layouts/` 配下にあるコンポーネントを優先して使用してください。

利用可能なレイアウトコンポーネント：

```text
components/
└── layouts/
    ├── Center/
    │   └── Center.tsx
    ├── Cluster/
    │   └── Cluster.tsx
    ├── Container/
    │   └── Container.tsx
    └── Stack/
        └── Stack.tsx
```

各コンポーネントの使い分けは以下を基本としてください。

| コンポーネント | 用途 |
| -------------- | ---- |
| `Center` | 子要素を中央に配置する場合 |
| `Cluster` | 子要素を横方向に並べ、まとまりとして配置する場合 |
| `Container` | コンテンツの最大幅や表示領域を制御する場合 |
| `Stack` | 子要素を縦方向に積み重ねて配置する場合 |

レイアウトの構成には、これらのコンポーネントの使用を優先し、目的に応じて適切に組み合わせてください。

### テキスト・リンクコンポーネントの使用

テキスト、見出し、リンクには、原則として `components/elements/` 配下の既存コンポーネントを使用してください。

`p`、`h1`～`h6`、`a` などの HTML 要素を直接使用して、独自にタイポグラフィやリンクのスタイルを定義することは避けてください。

利用可能な要素コンポーネント：

```text
components/
└── elements/
    ├── Heading/
    │   └── Heading.tsx
    ├── Link/
    │   └── Link.tsx
    └── Text/
        └── Text.tsx
```

各コンポーネントの使い分けは以下を基本としてください。

| コンポーネント | 用途 |
| -------------- | ---- |
| `Heading` | 見出し |
| `Text` | 本文や補足テキスト |
| `Link` | リンク |

### 実装ルール

- レイアウトには `Center`、`Cluster`、`Container`、`Stack` などの既存コンポーネントを使用する。
- 見出しには `Heading`、本文には `Text`、リンクには `Link` を使用する。
- 既存コンポーネントで実現できる機能を、HTML 要素や独自スタイルで再実装しない。
- 既存コンポーネントが必要な機能に対応していない場合は、既存コンポーネントの拡張、または再利用可能なコンポーネントの追加を検討する。
- その場限りの独自スタイルや実装（特に `className`）を増やさず、既存のコンポーネントやスタイリングの規約に従う。
- 既存コンポーネントの API や Props を確認し、実装されていない機能や Props を想定して使用しない。
- 実装が困難な場合は要相談。

### UI コンポーネントの入れ子に関するルール

UI の階層構造は、できるだけフラットで理解しやすい構成にしてください。

- モーダルの中に別のモーダルを配置しない。
- ツールチップの中に別のツールチップを配置しない。
- インタラクティブな UI コンポーネントを不必要に入れ子にしない。
- 同じ種類の UI コンポーネントを不必要にネストしない。

### Storybook について

`/ui` のコンポーネントを利用する場合は、`example/ui` に用意されている Storybook の実装例を参考にしてください。

Storybook では、各コンポーネントの使用方法や Props、組み合わせ方を確認できます。

独自の実装を行う前に、既存の Storybook を確認し、既存の実装パターンに合わせてください。

## テーブルの実装

テーブルを実装する場合は、原則として TanStack React Table（`@tanstack/react-table`）を使用してください。

基本的な実装方法は `example/table` を参考にしてください。

また、ソート・フィルタリング・ページネーションなどの機能については、`/lib/data-table-features.ts` を参考にしてください。

### 実装方針

- TanStack React Table を使用してテーブルを構築する。
- カラム定義は `columns.tsx` の実装例を参考にする。
- テーブル本体は `data-table.tsx` の実装例を参考にする。
- 共通化されているテーブル機能は `/lib/data-table-features.ts` を確認し、既存の実装を再利用する。
- 独自にソートやページネーションなどを実装する前に、既存の機能が利用できないか確認する。

### 参考ファイル

| ファイル | 役割 |
| -------- | ---- |
| `example/table/columns.tsx` | カラム定義の実装例 |
| `example/table/data-table.tsx` | テーブル本体の実装例 |
| `example/table/page.tsx` | テーブル画面の実装例 |
| `example/table/Table.stories.tsx` | Storybook の実装例 |
| `/lib/data-table-features.ts` | テーブル共通機能の定義 |

## Form の実装

フォームを実装する場合は、原則として React Hook Form（RHF）と Zod を組み合わせて使用してください。

フォームの状態管理・入力値の検証・型定義を一元管理することで、実装の一貫性を保ちます。

基本的な実装方法は `example/form` を参考にしてください。

### 推奨ライブラリ

| ライブラリ | 用途 |
| ---------- | ---- |
| React Hook Form | フォームの状態管理・入力値の管理 |
| Zod | 入力値のバリデーション・スキーマ定義 |
| @hookform/resolvers | Zod と React Hook Form の連携 |

### 実装方針

- フォームの状態管理には React Hook Form を使用する。
- バリデーションルールは Zod で定義する。
- `zodResolver` を使用して React Hook Form と Zod を連携する。
- フォームのスキーマ定義は `schema` ディレクトリに分離する。
- フォームロジックは必要に応じてカスタムフックに分離する。
- 入力 UI には原則として `/elements` のコンポーネントを使用する。

### 参考ディレクトリ

| ファイル | 役割 |
| -------- | ---- |
| `example/form/schema/formSchema.ts` | Zod スキーマ定義 |
| `example/form/hooks/useForm.tsx` | フォームロジック |
| `example/form/components/FormExample.tsx` | フォームコンポーネント |
| `example/form/pages/FormPage.tsx` | フォーム画面 |
| `example/form/Form.stories.tsx` | Storybook の実装例 |
| `example/form/components/FormExample.test.tsx` | テストの実装例 |

既存の実装パターンを参考にし、フォームごとに独自の状態管理やバリデーション処理を実装しないようにしてください。

## 選択コンポーネントの使い分け

適切な選択コンポーネントは、以下の観点で使い分けてください。

| コンポーネント | 値を複数選択できるか | 反映タイミング | 選択肢の数 | 検索機能 | 備考 |
| :------------- | :------------------- | :------------- | :--------- | :------- | :--- |
| `ComboboxMultiple` | 複数 | 送信時 | 6個以上 | あり | |
| `Checkbox` | 複数 | 送信時 | 5個以下 | なし | 例外として、「○○に同意する」などの二択の切り替え入力にも使用できる |
| `Switch` | 単一 | 即時 | 2個 | なし | |
| `Combobox` | 単一 | 送信時 | 6個以上 | あり | 選択肢が多く、キーワードで絞り込みたい場合（例：担当者名、プロジェクト名） |
| `Select` | 単一 | 送信時 | 6個以上 | なし | 「〇月」など、選択肢の順序が予測でき、検索が不要な場合に使用する |
| `Radio` | 単一 | 送信時 | 5個以下 | なし | |
